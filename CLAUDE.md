# Mountpoint – notes for working on the project

Mac-only menu bar app (own `NSStatusItem` + `NSPopover` with SwiftUI, `LSUIElement`), macOS 13+, universal (arm64 + x86_64). Sister project of MediaFiles Ferry, same typography and colors. GPL-3.0. Users are editors without a technical background.

## Fixed rules
- Never delete, move or overwrite files. Removing a workspace = remove the entry + eject. Only exception (owner, 2026-11-10): `Sidebar.purge` rewrites the Finder's FavoriteVolumes list to delete Mountpoint's own stale entries, with backups (`docs/release-1.3.0-changes.md` §3).
- Never force-eject (`/sbin/umount` without `-f`); "busy" → tell the user to quit Media Composer.
- Default: mount as network drive (no macFUSE `local` flag → macOS reports non-local, DiskArbitration network=1). Media Composer Enterprise (tested 2026.8) then creates "<computer name>.1" instead of "1". Setting `Store.network`; `local` only when switched off.
- Volume name = folder name, mount point `/Volumes/<name>`. An existing, non-empty entry there blocks mounting.
- Eject via `/sbin/umount`, not `unmount(2)`: only then does macOS remove the mount point folder (`/Volumes` is owned by root).
- NAS: when adding, store `volumeURLForRemounting` + subpath; when mounting, connect the share via NetFS.
- Protected volumes (`Guard.swift`): never scan. kqueue on the volume root (`O_EVTONLY`, does not block eject) + mount notifications + 60 s safety net. Snooze is per volume and persisted; alert again after the snooze; "OK" = only again when the folder is created anew.
- Always decode `Library` with `decodeIfPresent`: old files without new fields must still load.
- An unreadable `library.json` is set aside (`library-unreadable-<time>.json`) with a notice – never continue silently with an empty list (the next save would overwrite it).
- Errors must say what happened and what to do, in plain words (EN + DE); technical output goes after "Details:". Per-workspace errors show in the row, app-wide ones in `Store.notice` (banner in the panel; menu bar icon gets a dot). No `NSAlert` while the panel is open; on quit, an alert lists volumes that stay mounted.
- Protected volumes have a mode per volume: `Library.guarded` (names; `systemGuard` "/" = system volume, watched at `/Users/Shared/AvidMediaComposer`, shown under its Finder name via `guardName`) and `Library.guardOwn` (names watching only the own folder in MXF; `Library.watchesOwn` – always for the system volume, which shows no drop-down and no label; UI name "Workstation folder": exactly "1" on local volumes, exactly "<ComputerName>.1" (`SCDynamicStoreCopyComputerName`) on non-local ones). Setting `Store.watchNetwork` (default off): every mounted non-local volume with "Avid MediaFiles" warns about a new folder exactly "1" (someone without bin locking). All MXF watches are `FolderWatch` values from `Store.folderWatches()`; the known list is keyed by `FolderWatch.key` ("g:<name>", "net:<path>"). Alerts call `VolumeGuard.hold` (→ AppDelegate.hold) while open: the popover is transient and would close when the alert is clicked.
- Workspace errors can be dismissed: × in the row, "Clear error messages" in the project ⋯ menu (`Store.clearError`/`clearErrors(in:)`). They don't vanish on their own – a mount failure at launch must still be visible when the panel is opened later.
- MXF watches (`<volume>/Avid MediaFiles/MXF`, kqueue + 60 s): no per-workspace/project warning any more (removed in beta 13 at the user's request, old `warnNumbered` keys are ignored). Folders present when watching starts are "known", only new ones alert; "OK" adds them to the known list (UserDefaults `numberedKnown`); deleted folders are dropped from it, so recreating "1" alerts again.
- No trash: network-style volumes have none, deleting is permanent (the welcome panel says so, also for folders on local drives). A helper workaround that moved Finder deletions into the source volume's trash was removed in 1.0.0 beta 11 at the user's request (it failed for folders on NAS shares) – don't bring it back.
- `m_setxattr` strips `XATTR_NOSECURITY`/`XATTR_NODEFAULT`: the Finder passes them when copying (FinderInfo), `setxattr()` rejects kernel-only flags with EINVAL and the Finder fails with error -50 (`cp`/`ditto` never hit it – test copies with the Finder, e.g. `osascript … duplicate`).
- Self-test consent (`Consent.swift`): after the welcome panel on the first launch and once per new version (UserDefaults `selftestAskedFor`), a centered panel asks to run the self-test and send it anonymously; "Run self-test" runs and auto-sends (`SelfTest.autoSend`), "Not now" waits for the next version. Not shown for "dev" builds.
- First launch: `Welcome.swift` shows a centered panel ("deleting is permanent, keep a backup" + "use at your own risk") until "I understand" sets UserDefaults `welcomeConfirmed2` (new key when the text changes in substance, so everyone sees it again). Switching "Mount as network drive" on shows the `networkInfo` card.
- Updates (`Updater.swift`): GitHub releases API (prereleases included, drafts skipped), at launch + every 6 h and by hand in Settings. Install = download zip → `ditto` → check bundle id, `MountpointRelease` == tag and `codesign --verify --deep --strict` → old app to Trash, new one moved in its place (restored on failure) → remember mounted workspaces (UserDefaults `remountAfterUpdate`) → quit (ejects) → a shell waits for the pid and reopens; the new version mounts them again. Release tags must be `v<version>` and the asset `Mountpoint-<version>.zip`.
- Volume icon: steel grey, nearly square (anthracite vanished in dark Finder windows, wide shapes look tiny in column view); `scripts/make-volume-icon.swift` → `VolumeIcon.icns`, passed to the helper as `volicon` (otherwise Finder shows macFUSE's "FUSE" drive).

- Mount status comes from `Mounter.mounts()` (`getfsstat` with MNT_NOWAIT): it never asks a file system, so a hanging NAS or a stopped helper cannot freeze the app – never use `statfs()`/`mountedVolumeURLs` on the main thread for this. The helper mounts with `fsname=mountpoint@<workspace UUID>`; `Mounter.isMounted(w)` matches it, so two workspaces with the same folder name don't share a status (old "mirror@" mounts: by path).
- VolumeGuard reads folders only on its `io` queue (fileExists, MXF listings, opening kqueue fds); results are applied on the main thread, events during a scan coalesce into one more scan. Tests wait for `guardian.idle`.
- A crashed helper leaves a dead mount (ENXIO, "Device not configured"): `Store.findDeadHelpers` probes `lstat` of a random name below the volume in the background every refresh (the root itself still answers from the kernel's cache), ejects it and shows a row error.
- The probe also classifies: ENOENT = fine, ENXIO = dead (eject, row error, then auto-remount), network errors (`Store.unreachable`, e.g. ETIMEDOUT after the NAS cable is pulled) or no answer within 10 s = "not responding" row message that clears itself. A workspace ejected after an outage is in `Store.reconnect`: it is mounted again as soon as the drive with its folder is back in the mount table; for NAS workspaces Mountpoint also tries `Mounter.mountShare(interactive: false)` every 30 s (NetFS "UIOption"="NoUI": Keychain only, never a dialog). A user's own Eject clears it. Tested by pulling the network cable (2026-11-06).
- MXF folder size (setting `Store.watchSize`, default off, global): `VolumeGuard.checkSizes` (on every guard refresh, i.e. at least once a minute) counts the visible files of every subfolder of "Avid MediaFiles/MXF" on all non-hidden /Volumes mounts (not our own mirrors), the system volume and every workspace source (`Store.sizeRoots`), on its own `sizeIO` queue. `fileCount` counts readdir names like MediaFiles Check (visible files incl. the two database files; no dot files, no subfolders such as "Creating" – owner: "files starting with a dot never count"); a folder is recounted only when its mtime changed or after 10 min. Limit = setting `Store.sizeLimit` (100…50000, default 5000, like MediaFiles Check's rebalancing limit; number field inside the switch row "Warn about MXF folders with more than [5000] files", applied on Enter/leaving the field, invalid → red frame, then reverted). Details and acknowledgement rules: `docs/release-1.3.0-changes.md` §2. Over 90 % (`earlyLimit`, nil = 90 %) and below the limit → early alert ("start a new folder now"); exactly the limit never alerts and counts as an acknowledged early alert, so one file less does not warn either (MediaFiles Check fills folders that full); one file over the limit → alert; "OK" (`bigKnown`, persisted: path = limit, "~"+path = early) silences it until the folder drops below and crosses again – an acknowledged early alert still alerts once more over the limit.
- Finder sidebar (`Sidebar.swift`, setting `Store.sidebar`, default on): mounted workspaces are added to the LSSharedFileList `FavoriteVolumes` list behind "Locations" (how LucidLink does it; our volumes have no server URL; the macFUSE `local` flag would list them but breaks the network-drive rule). `Store.refresh` → `Sidebar.sync` reconciles on every change, quitting hides all own entries. macOS can only hide entries, never delete them, and "External disks" shows every hidden one again, so: an observer hides ghosts by name (`purgeNames`), and once per launch `Sidebar.purge` really deletes Mountpoint's stale entries from the sfl3 file (re-read and compare, two backups, write, `killall sharedfilelistd`). Rules a change must keep: only entries matching `isStale`; never write when the file changed or cannot be decoded; backups before the list; never on the main thread (quit waits at most 5 s); tests and the settings app never sync (`isShared, !passive`). Mechanism, guarantees, risks and restore: `docs/release-1.3.0-changes.md` §3, §5. The API is deprecated since 10.11 but works on macOS 15.
- Self-test (`SelfTest.swift`, Settings → Updates & support → "Run self-test…"): ~25 checks for testers without Xcode – system info, macFUSE, mount network/local, volume icon, sidebar probe (`Sidebar.probe`, never touches the owned list), data integrity, throughput, metadata, odd names, xattrs, overlong paths, Finder copy (asks once for Finder automation, skipped if denied), busy eject, cycles, parallel, same name, helper crash, hanging volume, guard alerts (protected, "1", size), update download + signature, optional NAS (only with consent, test folder on the first writable smbfs share). Everything runs on its own sparse APFS disk image (`hdiutil`, -nobrowse) in the temp folder; test volumes are named `MPSelftest-…`; all removed afterwards. Never touches the user's workspaces. Store.shared is only read inside the real app bundle (tests must not create it).
- Self-test "Send report" and the problem form show their result as the same toast (`Toast`/`.toast` in Support.swift, held by `SettingsPane`: 3 s success, 8 s failure) – inline text made the settings pane overflow; after a successful send the pane goes back to the Support overview. Support also has "Buy me a coffee" (`AboutView.coffee`, also near the top of the README). The "Mounted as network drive" notice in the settings window is a Ferry-style card (`networkCard`), not a system alert.
- Reports (`Reporter.swift`): self-test report and "Report…" problem form (text, optional email, optional anonymized system info + log) go as JSON to `Reporter.endpoint` (Cloudflare Worker in `worker/`, free plan), which validates, rate-limits (KV: 10 per IP, app and hour – one counter for all apps locked testers out –, 50 per day) and stores each report as a JSON file + issue in the PRIVATE repo moritz-poth/mountpoint-reports (fine-grained token only in the worker). Sending fails → the report is saved in Downloads. `anonymize()` replaces user name, computer name, folder/volume names in paths (hash ids, same name → same id) and server URLs; check new log lines with it. Evaluate with `gh issue list -R moritz-poth/mountpoint-reports`.
- Test versions: setting `Store.betas` ("Get test versions", default off); `newestRelease(includePrereleases:)` – prereleases only with the setting or when a prerelease is running. Publish test builds as GitHub prereleases.
- Eject runs in the background like mount (`busy`, button "Ejecting…"): umount on a hanging volume must not freeze the app.
- LucidLink 3 mounts via SMB on 127.0.0.1, one level deeper (`/Volumes/<filespace>/<project>`), non-local: protected-volume entries for such mount points are full paths (`guardEntry`/`guardRoot`).
- `helper/mirror.c`: paths longer than PATH_MAX return ENAMETOOLONG (never a truncated path); chmod/truncate never follow symlinks; `flush` passes close() errors (SMB reports write errors there) to the app.
- Log file `~/Library/Logs/Mountpoint/Mountpoint.log` (`Log.write`, rotated at 1 MB, only in the real app bundle – tests don't write it): start, mounts/ejects with errors, workspace/project/guard changes, alerts and snoozes, updates. Settings → "Show log file".
- Started from the DMG or an App Translocation path (`runsFromTemporaryPlace`, Model.swift): main.swift shows "Move Mountpoint to the Applications folder" and exits before anything loads (no mount, no sidebar, no updater).
- Update signature: `scripts/update-key.swift` (Ed25519, private key in the login Keychain, service "Mountpoint update key"); `Updater.publicKey` holds the public key; `newestRelease` ignores releases without `<zip>.sig`; `Updater.unpack` checks the signature before unzipping. build-app.sh signs only if the Keychain key matches `Updater.publicKey`, otherwise it prints "NOT SIGNED". Never replace the key (installed apps trust it); Developer ID + notarization is the planned later option. If the key is ever lost: delete the Keychain item, `update-key.swift new`, put the new public key into `Updater.publicKey`, build, and upload zip + `.sig` + an empty `Mountpoint-<version>.manual`. Older apps then show "This update has to be installed by hand" with a button to the project's GitHub releases (`Release.manual`/`safePage`: the text and link are fixed in the app, only the marker comes from GitHub; nothing is installed automatically).

## UI
- No `MenuBarExtra` and no `NSAlert` in the panel: both close the panel. Questions are `Dialog` cards in the panel (Panel.swift), the folder picker is `FolderBrowser` in the panel (no `NSOpenPanel`). Anything open outside the panel (NAS password) keeps it open via `hold(true)`.
- Drop-downs: `Dropdown` (Views.swift) = Menu with `.menuStyle(.button)` + `FerryButtonStyle`, own chevron, system indicator hidden – the borderless style added its own insets and never lined up. Visual check of menus: render with `NSHostingView.cacheDisplay` (ImageRenderer draws menus as placeholders) and register the fonts first.
- Appearance: the panel uses `Store.dark` directly (Theme + colorScheme), the popover appearance follows it; light/dark is a `SwitchRow` titled "Light/Dark" (on = dark), right-aligned like every other on/off option (`SwitchRow` (label left, switch right, whole row toggles) – no checkboxes). The ⋯ menu's "Mount at app launch" stays a native menu item with a check mark. Settings order (since 1.0.1): "Settings" (launch at login, appearance, language, Finder sidebar) → "Media Composer" (network drive, "1" warning, MXF folder size warning with limit) → "Protected volumes" (list, then "Protect another volume" text left + "Add volume…" right, like the version row) → "Updates & support"; rows with a button: short text left, button right-aligned. Main page footer (since 1.0.1): "Add…" drop-down (Add workspace… / New project…) left, "Quit" right – nothing else. "About Mountpoint" is in the settings footer (left of Done; its Done returns to the settings), "Show log file" in the "Updates & support" section – three buttons in one row do not fit in de/fr/es. The gear is filled only on the settings page; from every other page (About, folder picker) it leads to the settings.
- Settings live in their own window (`SettingsWindow.swift`, since 1.1.0): NSTabViewController with toolbar tabs (General, Avid Media Composer, Protected volumes, Updates, Support, About), title always "Mountpoint" (not the pane; app menu "Hide Settings"/"Quit Settings", no Window menu, ⌘W is a hidden item), minimize/zoom dimmed, last pane restored (UserDefaults `settingsPane`), 16:9 = 800×450 at the user's request (HIG would size per pane; long panes scroll), opened by the gear or ⌘, while the panel is open; the panel stays open (`hold`) while the window is open and the gear is filled. Since 1.2: the settings run as their own app – `Mountpoint.app/Contents/Helpers/Mountpoint Settings.app` (built by build-app.sh: same binary, bundle id `…mountpoint.settings`, regular app with Dock icon, ⌘-Tab and menu bar, named just "Mountpoint" in the menu bar, Dock and ⌘-Tab (owner, 2026-11-10: users only know the menu bar app) via InfoPlist.strings in every language – the unlocalized `CFBundleDisplayName` must stay "Mountpoint Settings" (= file name), otherwise the Dock ignores the localized name). `settingsMode` (Model.swift) switches the code: `SettingsAppDelegate` shows only the window and quits when it closes; `Store.shared` is passive there (no refresh timer, no mounting, no guard, no sidebar). Both processes share one defaults domain (`defaults` = UserDefaults(suiteName: mainBundleID) in the settings app – never use UserDefaults.standard except for the process's own AppleLanguages) and library.json. IPC (`IPC.swift`, DistributedNotificationCenter): every library save posts "library", every setting change in the settings app posts "settings" (`announce()`), the other side calls `reloadLibrary()`/`reloadSettings()` (assigns only differences, so didSet effects run once); jobs only Mountpoint may do go as "launchAtLogin" (SMAppService from the settings app would register the settings app) and "showUpdate"; Mountpoint listens before `Store.shared` loads and posts "library" once at start; Mountpoint mirrors the login-item state in `launchAtLoginState`. `SettingsLauncher` (Mountpoint side) opens the settings app (pane via `--pane` or IPC "pane"), knows whether it runs (gear filled); the panel closes when the settings app opens and does not open again when it is closed (removed in 1.2.1 at the user's request). Development builds without the helper bundle fall back to the in-process `SettingsWindow` (accessory, level above the popover, hides on deactivate). Self-test paths (helper, volume icon) come from `mainBundleURL`. Field ownership is enforced in `Store.merged(onto:)`: `projects`/`workspaces` always come from Mountpoint's memory and, in the settings app, always from the file (it never writes its own copy); `guarded`/`guardOwn` from memory only if changed since the last load/save (`loaded` snapshot). `Store.save()` does this under `library.json.lock` after re-reading the file – never write the whole library blindly. `readDisk()` tells missing (ENOENT) from unreadable (any other error, bad JSON): unreadable is never written over: the passive store becomes `readOnly` (guard edits refused before memory changes, posts "library" so Mountpoint repairs); Mountpoint at save/reload moves it aside under the lock (and saves at once when a reload finds projects/workspaces different from its own; `knowsList` false after an unreadable start it could not set aside: the first readable file supplies them); the settings app posts "library" when a reload finds the file missing; a cleared login notice brings back the read-only notice; (`setAside`, write only after a successful move) and writes its in-memory list; missing: both write `loaded` (by ownership no workspaces from the settings app), Mountpoint re-creates it on reload; a successful reload ends read-only. Self-test guards other than the size check pass `sizeRoots: { [] }` (never alert on real folders). `Updater.dismissed` = update notice closed; "showUpdate" resets it. Settings-app errors show as a banner in the settings window (`store.notice`). Launch at login: requests carry an `id`; Mountpoint always answers `launchAtLoginResult` (real state + error + id, no panel notice for settings-app requests); the settings app takes switch/error only from the answer to its pending request, reverts to the last confirmed state after 3 s ("did not answer"), clears only its own notice, and asks `launchAtLoginQuery` at launch. `reloadSettings` neither announces nor logs (`reloading`). Mountpoint asks the settings app to quit on quit (`SettingsLauncher.terminateRunning`); no update while a self-test runs anywhere (`SelfTest.runningAnywhere`), before the swap `terminateRunning(wait: true)` waits 5 s then force-quits; Mountpoint's own quit waits for its self-test; "Show in Mountpoint" starts Mountpoint with `--show-update` if needed; if opening it fails, the in-process window opens instead. Self-test: one at a time across processes (`flock` on `$TMPDIR/Mountpoint-Selftest.lock`, `blocked`), its guards use `VolumeGuard(persist: false)`, the settings window does not close while it runs (`windowShouldClose` shows a notice and closes it afterwards; ⌘Q `.terminateLater`). Log: `O_APPEND`, one write per line, rotation under `Logs/Mountpoint/.lock`, settings-app lines tagged `[settings]`. Release review doc: `docs/release-1.2.0-changes.md` (guarantees G2–G7). Tests: SettingsAppTests (field ownership without reload, read-only, passive never mounts, self-test lock, guard persistence, login-item timeout). Panes never scroll (content fits 800×370 below the toolbar); only the protected-volume list scrolls (max 180 pt) with “Add volume…” always below it. Floating panels (welcome, consent, guard alerts) set `hidesOnDeactivate = false` – NSPanel would vanish while Mountpoint is in the background (launch after an update, system permission prompts). Content keeps the Ferry look (`SettingsPane`). Questions inside the window may use SwiftUI `.alert` (the no-NSAlert rule is only for the popover). The folder picker still replaces the panel content; closing the popover resets to the main page. The picker starts at `Store.lastFolder` and keeps one fixed height on every level (466 pt): the header has a fixed height (the drive list shows "Choose a volume" flush left, deeper levels the back chevron + folder name), the NAS "Connect" row is shown on every level, "New folder" is an icon (folder.badge.plus) at the right of the header and its form overlays the bottom of the folder list – nothing may appear or vanish below the list when changing level, the panel would jump.
- Dots: filled green = all mounted, grey ring = none, half-filled orange (`Theme.partial`) = partly / problem – the shape carries the state too (HIG: not by color alone), each dot has a VoiceOver label. Text colors meet 4.5:1 in both modes (`faint` dark, `partial`/`online` light were raised in 1.0.1), no text below 10 pt. Projects are collapsed by default; expanded ones stay expanded across launches.
- Colors only from `Theme` (Views.swift), font `Font.mono` (JetBrains Mono), title Helvetica Neue Light. Default: dark.
- UI strings are English in code, translations in `Resources/<code>.lproj/Localizable.strings` (de, fr, es) – update all of them with every new string (`LocalizationTests` fails otherwise). Language is selectable (default English, `languages` in Model.swift); switching is live: root views get `.environment(\.locale, store.locale)`, non-`Text` strings go through `loc()` (Model.swift, `languageBundle`) – never `String(localized:)` directly. Messages already shown stay in the old language. Expanded projects are remembered (UserDefaults `expanded`).
- Wording (user rule 2026-11-07): Avid is the company, Media Composer the program – write "Media Composer" (or "Avid Media Composer"), never "Avid" for the program. Features only Media Composer Enterprise has (bin locking, "<computer name>.1" folders on network drives) say "Media Composer Enterprise". "Avid MediaFiles" is a folder name and stays. Same in README and all four languages.
- Visual check: temporarily render the panel with `ImageRenderer` to PNG, then remove the hook again.

## Icon
"Folder drive" (concept 8 of 20, chosen 2026-11-07; replaced N01): a drive whose top has a folder tab, tab slant exactly 45°, one shared geometry in a 256-unit grid (body 40…216 × 100…196, tab to y 80, LED at 180/164). App icon (variant B, solid): `scripts/make-icon.swift` → `assets/icon.png` (Apple grid: 824 px plate, shadow, gradient, light edge), light solid motif, green LED #1a7f37, seam line only from 64 px. Menu bar: `menuBarIcon()` in main.swift (= `assets/menubar.svg`), template image: outline = nothing mounted, filled with punched-out LED = mounted, dot top right = problem. Volume icon (volume B, adjusted): `scripts/make-volume-icon.swift` – the volume itself has the folder-drive shape, steel grey, dark drive base with light seam and green LED; own cut for 16/32 px (higher base, bigger LED, no shadow/edge) so it never reads as a plain folder in the sidebar. Checked in the real Finder (NSWorkspace icon of a mounted test volume). The other apps' icons are to be adapted to this style later.

## Build / test
`scripts/build-app.sh` (universal app + zip for the updater + dmg for downloads: app next to an Applications link below the title "MOUNTPOINT" (Helvetica Neue Light like the panel) with a dry-brush arrow (`scripts/make-dmg-background.swift`, fixed seed; transparent picture = Finder shows white, which keeps the item names readable – Finder draws them black on any background picture, even in dark mode), window layout set via Finder AppleScript, needs Finder automation once; upload dmg, zip and .sig), `swift test`, `MOUNTPOINT_IT=1 swift test` (really mounts). Stress test before a release: `MOUNTPOINT_STRESS=1 swift test --filter StressTests` (StressTests.swift: data integrity, throughput, metadata storm, odd names, xattrs, overlong paths, mount cycles, parallel mounts, same folder name, helper crash, hanging volume, guard folder storm; measurements print as "STRESS …" lines). Overnight soak test of the real app: `python3 scripts/soak-test.py /Volumes/<empty test workspace> [--hours 10]` (MC-like capture/playback/bin saves, checks data via the volume and the source folder, samples app/helper memory; refuses non-empty workspaces; report in `~/Library/Logs/Mountpoint/soak-<time>-<volume>/`; one instance per volume can run in parallel, `--clip-scale`/`--rate` for cloud volumes). Only Swift Testing is available (Command Line Tools, no XCTest). Release: bump `VERSION`/`RELEASE`/`BUILD` in the build script.
