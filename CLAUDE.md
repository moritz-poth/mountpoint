# Mountpoint – notes for working on the project

Mac-only menu bar app (own `NSStatusItem` + `NSPopover` with SwiftUI, `LSUIElement`), macOS 13+, universal (arm64 + x86_64). Sister project of MediaFiles Ferry, same typography and colors. GPL-3.0. Users are editors without a technical background.

## Fixed rules
- Never delete, move or overwrite files. Removing a workspace = remove the entry + eject.
- Never force-eject (`/sbin/umount` without `-f`); "busy" → tell the user to quit Media Composer.
- Default: mount as network drive (no macFUSE `local` flag → macOS reports non-local, DiskArbitration network=1). Media Composer Enterprise (tested 2026.8) then creates "<computer name>.1" instead of "1". Setting `Store.network`; `local` only when switched off.
- Volume name = folder name, mount point `/Volumes/<name>`. An existing, non-empty entry there blocks mounting.
- Eject via `/sbin/umount`, not `unmount(2)`: only then does macOS remove the mount point folder (`/Volumes` is owned by root).
- NAS: when adding, store `volumeURLForRemounting` + subpath; when mounting, connect the share via NetFS.
- Protected volumes (`Guard.swift`): never scan. kqueue on the volume root (`O_EVTONLY`, does not block eject) + mount notifications + 60 s safety net. Snooze is per volume and persisted; alert again after the snooze; "OK" = only again when the folder is created anew.
- Always decode `Library` with `decodeIfPresent`: old files without new fields must still load.
- An unreadable `library.json` is set aside (`library-unreadable-<time>.json`) with a notice – never continue silently with an empty list (the next save would overwrite it).
- Errors must say what happened and what to do, in plain words (EN + DE); technical output goes after "Details:". Per-workspace errors show in the row, app-wide ones in `Store.notice` (banner in the panel; menu bar icon gets a dot). No `NSAlert` while the panel is open; on quit, an alert lists volumes that stay mounted.
- Protected volumes have a mode per volume: `Library.guarded` (names; `systemGuard` "/" = system volume, watched at `/Users/Shared/AvidMediaComposer`, shown under its Finder name via `guardName`) and `Library.guardOwn` (names watching only the own folder in MXF; `Library.watchesOwn` – always for the system volume, which shows no drop-down and no label; UI name "Workstation folder": exactly "1" on local volumes, exactly "<ComputerName>.1" (`SCDynamicStoreCopyComputerName`) on non-local ones). Setting `Store.watchNetwork` (default off): every mounted non-local volume with "Avid MediaFiles" warns about a new folder exactly "1" (someone without bin locking). All MXF watches are `FolderWatch` values from `Store.folderWatches()`; the known list is keyed by `FolderWatch.key` ("g:<name>", "net:<path>"). Alerts call `VolumeGuard.hold` (→ AppDelegate.hold) while open: the popover is transient and would close when the alert is clicked.
- Workspace errors can be dismissed: × in the row, "Clear error messages" in the project ⋯ menu (`Store.clearError`/`clearErrors(in:)`). They don't vanish on their own – a mount failure at launch must still be visible when the panel is opened later.
- MXF watches (`<volume>/Avid MediaFiles/MXF`, kqueue + 60 s): no per-workspace/project warning any more (removed in beta 13 at the user's request, old `warnNumbered` keys are ignored). Folders present when watching starts are "known", only new ones alert; "OK" adds them to the known list (UserDefaults `numberedKnown`); deleted folders are dropped from it, so recreating "1" alerts again.
- No trash: network-style volumes have none, deleting is permanent (the welcome panel says so, also for folders on local drives). A helper workaround that moved Finder deletions into the source volume's trash was removed in 1.0.0 beta 11 at the user's request (it failed for folders on NAS shares) – don't bring it back.
- `m_setxattr` strips `XATTR_NOSECURITY`/`XATTR_NODEFAULT`: the Finder passes them when copying (FinderInfo), `setxattr()` rejects kernel-only flags with EINVAL and the Finder fails with error -50 (`cp`/`ditto` never hit it – test copies with the Finder, e.g. `osascript … duplicate`).
- First launch: `Welcome.swift` shows a centered panel ("deleting is permanent, keep a backup" + "use at your own risk") until "I understand" sets UserDefaults `welcomeConfirmed2` (new key when the text changes in substance, so everyone sees it again). Switching "Mount as network drive" on shows the `networkInfo` card.
- Updates (`Updater.swift`): GitHub releases API (prereleases included, drafts skipped), at launch + every 6 h and by hand in Settings. Install = download zip → `ditto` → check bundle id, `MountpointRelease` == tag and `codesign --verify --deep --strict` → old app to Trash, new one moved in its place (restored on failure) → remember mounted workspaces (UserDefaults `remountAfterUpdate`) → quit (ejects) → a shell waits for the pid and reopens; the new version mounts them again. Release tags must be `v<version>` and the asset `Mountpoint-<version>.zip`.
- Volume icon: steel grey, nearly square (anthracite vanished in dark Finder windows, wide shapes look tiny in column view); `scripts/make-volume-icon.swift` → `VolumeIcon.icns`, passed to the helper as `volicon` (otherwise Finder shows macFUSE's "FUSE" drive).

- Mount status comes from `Mounter.mounts()` (`getfsstat` with MNT_NOWAIT): it never asks a file system, so a hanging NAS or a stopped helper cannot freeze the app – never use `statfs()`/`mountedVolumeURLs` on the main thread for this. The helper mounts with `fsname=mountpoint@<workspace UUID>`; `Mounter.isMounted(w)` matches it, so two workspaces with the same folder name don't share a status (old "mirror@" mounts: by path).
- VolumeGuard reads folders only on its `io` queue (fileExists, MXF listings, opening kqueue fds); results are applied on the main thread, events during a scan coalesce into one more scan. Tests wait for `guardian.idle`.
- A crashed helper leaves a dead mount (ENXIO, "Device not configured"): `Store.findDeadHelpers` probes `lstat` of a random name below the volume in the background every refresh (the root itself still answers from the kernel's cache), ejects it and shows a row error.
- The probe also classifies: ENOENT = fine, ENXIO = dead (eject, row error, then auto-remount), network errors (`Store.unreachable`, e.g. ETIMEDOUT after the NAS cable is pulled) or no answer within 10 s = "not responding" row message that clears itself. A workspace ejected after an outage is in `Store.reconnect`: it is mounted again as soon as the drive with its folder is back in the mount table; for NAS workspaces Mountpoint also tries `Mounter.mountShare(interactive: false)` every 30 s (NetFS "UIOption"="NoUI": Keychain only, never a dialog). A user's own Eject clears it. Tested by pulling the network cable (2026-11-06).
- MXF folder size (setting `Store.watchSize`, default off, global): `VolumeGuard.checkSizes` (on every guard refresh, i.e. at least once a minute) counts the entries of every subfolder of "Avid MediaFiles/MXF" on all non-hidden /Volumes mounts (not our own mirrors), the system volume and every workspace source (`Store.sizeRoots`), on its own `sizeIO` queue. `entryCount` uses getattrlist ATTR_DIR_ENTRYCOUNT (APFS/HFS) or counts readdir names (SMB, macFUSE don't support it); a folder is recounted only when its mtime changed or after 10 min. Over `sizeLimit` (5000) → alert; "OK" (`bigKnown`, persisted) silences it until the folder drops below and crosses again.
- Eject runs in the background like mount (`busy`, button "Ejecting…"): umount on a hanging volume must not freeze the app.
- LucidLink 3 mounts via SMB on 127.0.0.1, one level deeper (`/Volumes/<filespace>/<project>`), non-local: protected-volume entries for such mount points are full paths (`guardEntry`/`guardRoot`).
- `helper/mirror.c`: paths longer than PATH_MAX return ENAMETOOLONG (never a truncated path); chmod/truncate never follow symlinks; `flush` passes close() errors (SMB reports write errors there) to the app.
- Log file `~/Library/Logs/Mountpoint/Mountpoint.log` (`Log.write`, rotated at 1 MB, only in the real app bundle – tests don't write it): start, mounts/ejects with errors, workspace/project/guard changes, alerts and snoozes, updates. Settings → "Show log file".
- Update signature: `scripts/update-key.swift` (Ed25519, private key in the login Keychain, service "Mountpoint update key"); `Updater.publicKey` holds the public key; `newestRelease` ignores releases without `<zip>.sig`; `Updater.unpack` checks the signature before unzipping. build-app.sh signs only if the Keychain key matches `Updater.publicKey`, otherwise it prints "NOT SIGNED". Never replace the key (installed apps trust it); Developer ID + notarization is the planned later option. If the key is ever lost: delete the Keychain item, `update-key.swift new`, put the new public key into `Updater.publicKey`, build, and upload zip + `.sig` + an empty `Mountpoint-<version>.manual`. Older apps then show "This update has to be installed by hand" with a button to the project's GitHub releases (`Release.manual`/`safePage`: the text and link are fixed in the app, only the marker comes from GitHub; nothing is installed automatically).

## UI
- No `MenuBarExtra` and no `NSAlert` in the panel: both close the panel. Questions are `Dialog` cards in the panel (Panel.swift), the folder picker is `FolderBrowser` in the panel (no `NSOpenPanel`). Anything open outside the panel (NAS password) keeps it open via `hold(true)`.
- Drop-downs: `Dropdown` (Views.swift) = Menu with `.menuStyle(.button)` + `FerryButtonStyle`, own chevron, system indicator hidden – the borderless style added its own insets and never lined up. Visual check of menus: render with `NSHostingView.cacheDisplay` (ImageRenderer draws menus as placeholders) and register the fonts first.
- Appearance: the panel uses `Store.dark` directly (Theme + colorScheme), the popover appearance follows it; light/dark is a `Switch` (Views.swift); every other on/off option is a `SwitchRow` (label left, switch right, whole row toggles) – no checkboxes. The ⋯ menu's "Mount at app launch" stays a native menu item with a check mark. About is a button at the bottom left of the main page.
- Settings and folder picker replace the panel content (no separate windows: they slip behind the panel). Closing the popover resets to the main page (settings save immediately). The picker starts at `Store.lastFolder`.
- Dots: green = all mounted, grey = none, orange (`Theme.partial`) = partly / problem. Projects are collapsed by default.
- Colors only from `Theme` (Views.swift), font `Font.mono` (JetBrains Mono), title Helvetica Neue Light. Default: dark.
- UI strings are English in code, translations in `Resources/<code>.lproj/Localizable.strings` (de, fr, es) – update all of them with every new string (`LocalizationTests` fails otherwise). Language is selectable (default English, `languages` in Model.swift); switching restarts the app via `AppleLanguages`, volumes stay mounted.
- Visual check: temporarily render the panel with `ImageRenderer` to PNG, then remove the hook again.

## Icon
N01, drawn by `scripts/make-icon.swift` → `assets/icon.png` (Apple grid: 824 px plate, shadow, gradient, light edge) → AppIcon.icns in the build script. Menu bar: `menuBarIcon()` in main.swift draws the same motif as a template image; mounted = drive filled. Folder lines have flat ends.

## Build / test
`scripts/build-app.sh` (universal app + zip), `swift test`, `MOUNTPOINT_IT=1 swift test` (really mounts). Stress test before a release: `MOUNTPOINT_STRESS=1 swift test --filter StressTests` (StressTests.swift: data integrity, throughput, metadata storm, odd names, xattrs, overlong paths, mount cycles, parallel mounts, same folder name, helper crash, hanging volume, guard folder storm; measurements print as "STRESS …" lines). Only Swift Testing is available (Command Line Tools, no XCTest). Release: bump `VERSION`/`RELEASE`/`BUILD` in the build script.
